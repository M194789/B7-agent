# 知衡 · 多平台考核数据整合工作台

B7 初赛本地 Demo。任课老师、辅导员、教务处等评分方共用一个入口：把各平台、各种格式的材料一起交上来，用自己的话写评分规则，系统自动整合、去重、按规则算分，只在一页上请用户确认规则理解和真正需要决定的问题。每一分都能追到原始记录。

## 使用

1. 双击 `启动Demo.cmd`，打开 http://127.0.0.1:8017/。
2. 在“模型设置”连接 DeepSeek（`deepseek-flash`，支持图片）或其他兼容接口。照片、PDF 识别和理解评分规则需要模型；只有表格、不写规则时不连模型也能整合。
3. “新建任务”：拖入全部材料（成绩表、平台导出、照片、PDF、证书、工作记录、名单可以混在一起），在“评分规则”里写一句话或粘贴整份考核方案，点“开始处理”。也可以直接运行三个样例。
4. 系统自动判断是“课程成绩总评”还是“工作考核评分”，处理完后给出一页确认：我对规则的理解（不对就用一句话改，如“期中改成30%”）、需要你决定的问题（能给建议的已预选）、按当前规则的结果预览。判断错了可以一键切换。
5. 确认后导出：课程总评表 / 评分汇总表 CSV、整合记录表、报告 HTML、完整证据 JSON。

首次在其他电脑运行需安装 Python 3.12 或更新版本，启动脚本会创建本地虚拟环境并安装锁定依赖（本机已用 Python 3.13 验证）。停止服务可双击 `停止Demo.cmd`。

## 处理流程

```text
一个入口：材料（任意格式，混在一起）+ 评分规则（一句话或整份方案）
  → 自动判断：课程成绩总评 / 工作考核评分（显示依据，可切换）
  → 自动读取：表格直接读；照片、扫描 PDF 由模型识别；名单表自动认出
  → 自动整合：各列含义自动判定（不再逐表确认）、对照名单认人、去重、找冲突、识别缺考/缓考/未交等状态
  → 模型把规则或方案译成可计算的规则；程序按规则试算
  → 一页确认：规则的大白话理解 + 需要决定的问题（有建议的已预选）+ 结果预览；可用一句话修改规则
  → 程序精确计算 → 导出结果与依据
```

只有系统确实看不出哪一列是学生或成绩时，才会先问一句“学号/姓名/成绩在哪一列”。各表的列含义作为“系统的理解”折叠在确认页，不对可以改。

分工原则：模型负责读照片、认表头、理解规则文字；分数计算全部由程序完成；无法从材料核实的问题交给老师决定。

## 已实现

- 输入：CSV/TSV/XLSX/XLS（含教务系统导出的“HTML 冒充 .xls”）；Word 表格（直接读取，不经模型）；PDF 成绩单（逐页识别，有文字层时以文字层校对单元格，扫描件按图片识别）；JPG/PNG/WEBP 照片（按拍摄方向自动转正并压缩后识别）；不确定的单元格进入复核；可选课程名单（学号+姓名）。单任务最多 40 个文件、单文件 20MB、单表 10000 行、单份 PDF 30 页。
- 表格整理：自动找到表头所在行（跳过“××课程成绩登记表”等标题行）；两级合并表头（“实验成绩”下分“实验1/2/3”）自动合并；“平均分/合计/签字”等统计行不当作学生；PDF 第 2 页没有重复表头时沿用上一页表头并拼成一张表。所有自动整理都写在确认页“系统对每份材料的理解”里。
- 等级制成绩：A/B/C、优/良等在整合时识别为“等级”，由程序按规则中的等级表换算（模型只负责从规则原文读出这张表）；规则外的等级（如 D）、等级栏填了数字，逐条指出文件和行号请老师决定。各次作业可等权，也可按各次权重加权。
- 问答 / 点名日志：每行一次回答的记录表、白纸上只写名字或学号的照片、在名单上打勾，都能按“一次一条”计数；同一列混写学号和姓名时对照名单区分；同一天同一题只算一次，同名无法确定时请老师指定。只写姓名的记录必须有学生名单，没有名单时直接提示补传。
- 平台来源：模型判断每张表来自哪个平台（学习通、慕课/MOOC 等不同叫法）以及哪一列是平台算好的总评，分项名带上平台前缀（“学习通·视频学习”），不会和别的平台或老师的课堂作业混淆。有平台总评可直接用；只有分项而规则没给分项权重时，程序会明确要求老师给权重；给了分项权重就两级计算（分项先保留 2 位再加权），并核对平台总评与重算值，不一致的逐人列出。
- 缺失与 0 分：没有记录默认记 0 分（规则另有约定的按规则），缺考记 0 分、缓考待定；所有 0 分和“待定”集中列在确认页，原本有成绩只是没导出的可以直接补录，结果出来后仍可逐人逐项修改（程序重算并记入审计）。读取失败的文件单独标红，避免把“没读出来”当成“没有记录”。总评默认保留 2 位小数，确认页可直接改。
- 平台宽表：“小测1（10分）”“作业2”这类每列一次考核的导出，按列展开为记录，列名数字作为次序、括号内作为满分。
- 业务键：学号、课程、学期、考核项目、次序/日期、考试批次。同一次小测从两个平台导出会合并；第 1、2 次小测分别保留。
- 课程名单：只写姓名的记录在名单中唯一匹配；同名、查无此人、学号不在名单、学号与姓名不符都会提示；名单中没有任何记录的学生单独列出。
- 考试状态：缺考、缓考、作弊、免修、取消资格、未交（作业/实验）作为状态记录，不当作分数或错误；同一条记录同时出现“缺考”和“缓考”时交老师确认。
- 冲突：同一考核在不同来源中分数或状态不一致、同学号不同姓名，均需老师选择。
- 总评规则：组成项、权重、计算方式（平均/最高/最低/最后一次/去掉最低后平均/累加/按次数）、满分、没有记录时的处理（记 0 分或总评待定）、各状态的处理、保留小数。权重合计必须为 100%，同一考核项目不能计入两个组成项。
- 计算：学生漏交某次小测时按“没有记录时”的规则处理并在说明中写明；补考成绩不并入总评、单独标注。每个学生的总评可展开查看每个组成项的计算方式和原始来源。
- 任务、执行记录、人工决定和 LangGraph 暂停检查点持久化；执行记录区分规则处理、实际模型调用和人工确认。

## 工作考核评分（评分人使用）

面向给辅导员、教师打分的评分方（学院考核小组、教务处等），与课程总评共用同一个入口。流程：

```text
考核方案原文 → 模型拆成指标（按项计分 / 材料齐全度 / 评分人评价）
  → 模型逐份阅读材料：归属谁、什么材料、哪个比赛/项目、什么级别、对应哪个指标，摘录原文并核对
  → 程序计算：同一项目的多份证书合并计 1 项；同一成果按最高级别计、不累计；缺材料按方案扣分
  → 评价类指标：方案有标准时模型给出建议等级并预填分数，没有标准时只整理材料
  → 一页确认：指标的大白话理解（可一句话修改，修改后自动按新指标重新整理材料）、需要打分的项、需要留意的材料、目前得分
  → 导出评分汇总表、每人的评分依据与材料清单
```

- 被考核人名单可以不填：先从“姓名_材料”这类文件名识别，再不行由模型从材料内容中识别，确认页列出供核对。
- 材料：PDF（文字版读文字，扫描页按图片识别）、Word .docx（正文、表格，以及粘贴在文档里的证书图片）、TXT/MD 文本、CSV/TSV/XLS/XLSX、JPG/PNG/WEBP 照片，每个任务最多 40 份、单份 20MB。需要连接模型。
- 模型摘录的原文会和材料文本逐字比对，标出“原文核对一致 / 原文中未找到 / 来自图片，无法逐字比对”。
- 结果页统计“建议等级被采纳”次数，可作为评分人检验模型建议是否可靠的校准信号。
- 样例：合成的“示例学院辅导员考核方案”（9 个指标，100 分）和 3 名辅导员的 30 份材料，预设同一项目两张证书、两人申报同一项目、同一论文发两刊、校级奖不计分、缺谈话记录、缺普测材料、未署名材料等情况。由 `scripts/make_appraisal_fixtures.py` 生成（需要 Pillow）。

2026-10-22 实际模型验证（DeepSeek `deepseek-flash`，辅导员样例）：方案拆成 9 个指标且计分方式、扣分、等级标准与原文一致，并列出 7 处方案未说清的地方；30 份材料约 40 秒读完，归属与指标对应全部正确，系统标出的 5 份材料正是预设问题；程序计算的各项得分与方案一致；建议等级共 4 项，摘录原文全部核对一致。只覆盖一套合成材料，不代表真实材料的准确率。

## 能力边界测试（外部数据集）

用户提供的“两个50人班级的数据整合能力边界测试”（`../数据整合测试/`，合成数据，各班 7 个来源、层级权重、ABC 作业、问答日志，并埋入 20/18 个问题）。系统只拿到待测输入和规则原文；老师的决定由脚本按数据集给出的真实情况作答，计算全部由系统完成，再用数据集自带的 `评测结果.py --stage repaired` 对照“教师确认后标准结果”。

2026-10-22 结果：A 班 50 人 × 7 项成绩与标准结果 0 处差异；B 班只有 1 名学生的问答成绩（及其总评）不同，正是数据集说明中“系统不可能发现”的那一项（老师把 9 号的回答记成了另一个真实存在的学号）。可自动发现的问题均已列出：重复导出、身份不符、不存在的学号、同名、超满分、负分、空分、中文分数、满分为 0、规则外等级、等级栏填数字、冲突记录、平台总评与明细不一致、整人或单项缺失、缓考待定。

## 效果评测

左侧“效果评测”页（或命令行 `.venv/Scripts/python.exe -X utf8 -m eval.run --repeat 3`，模型由 `B7_LLM_*` 环境变量给出）用 7 个带标准答案的合成用例衡量每个模型环节：

| 用例 | 考察点 |
| --- | --- |
| A1 数据结构课程总评 | 演示样例：宽表、长表、手记照片、名单；同名、录错学号、超满分、名单外、冲突 |
| A2 实验课 | 两页扫描 PDF（续页无表头、平均分行）+ 教务系统 HTML 版 .xls（标题行、补考、缺考、免修） |
| A3 手写考勤照片 | 斜拍、手画勾、列名只有日期、同名学生写了班级、名单外学生；考勤按次数折算 |
| A4 陌生表头 | 拼音首字母表头、英文平台导出、表头写权重、备注写缺考/作弊、前导零学号、无名单；规则说“六成”“两成” |
| A5 规则超出能力 | 规则里有“酌情加分”“低于40分按期末记”：应指出交给老师，而不是编造计算 |
| B1 辅导员考核 | 演示样例：30 份材料、7 类预设问题 |
| B3 文件名无姓名 | 同 B1 材料，改成“扫描文档_01.pdf”“IMG_0412.jpg”等文件名并部分转为 PDF/Word/扫描件 |

做法：系统按真实流程处理；复核环节由脚本按标准答案作答（相当于一位认真对照原件的老师），所以每个环节的错误都在发生处被计数，不会被后面的人工复核掩盖。标准记录与总评不是手填的，而是用照片背后的干净数据、确认的字段对应、预设的老师决定和标准规则，由确定性引擎算出（另有单元测试对其中几名学生做了手算核对）。评测在临时数据目录中运行，不影响工作台里的任务。用例文件由 `eval/make_cases.py` 生成，标准答案在 `eval/cases.py`，结果保存在 `eval/results/`。

## 模型与数据

模型调用会发送：字段识别时的表头与两行样例；照片原图；规则理解时老师的规则文字和数据中出现的考核项目名称及次数（不含学生信息）。演示请使用合成或脱敏数据。

凭据仅保存在服务进程内存，不写入任务、导出报告或浏览器存储；重启后需重新填写。也支持 `B7_LLM_BASE_URL`、`B7_LLM_MODEL`、`B7_LLM_API_KEY` 环境变量。默认只监听本机。

## 已知限制

- 同一学生同一天答问两次、且记录里没有区分时，会被当作重复合并（需要老师在记录中写明次序）。
- 没有课程名单时，只写姓名的记录无法确认身份；写错的学号若恰好是另一名真实学生，系统无法发现。
- 一个任务内的多门课使用同一套总评规则。
- 尚未实现：跨平台账号与学号对应、课程替代、学校特定补考折算、三级及以上表头、旧版 .doc、iPhone HEIC 照片（需先转成 JPG）。
- 工作考核：没有正式的“先评几份再批量”校准流程（目前只统计采纳次数）；材料较多时每份一次模型调用，30 份约 40 秒；任课教师考核尚无专用样例，可用同一流程配一套教师考核方案。
