# B7「知衡」教学数据整合 Agent：集成说明（给负责合并打包的 AI）

本文说明 B7 子系统是什么、怎么启动、对外有哪些接口、合并时哪些地方不能动。合并前请先通读，有冲突时以本文和代码为准，README 中“效果评测”一节已过时（该页面已删除）。

## 1. 它做什么

一个本地 Web 工作台，一个入口，两条流程，由系统自动判断走哪条（用户可切换）：

| 流程 | `kind` | 使用者 | 输入 | 输出 |
|---|---|---|---|---|
| 课程成绩总评 | `grades` | 任课教师、教务 | 多个平台导出的成绩表（CSV/XLS/XLSX）、照片、PDF、Word 表格、课程名单 + 一句话或一段评分规则 | 总评表、整合记录、报告、证据 |
| 工作考核评分 | `appraisal` | 考核小组、教务处 | 考核方案原文 + 被考核人的证明材料（PDF/Word/图片/文本/表格） | 评分汇总表、每人的评分依据与材料清单 |

分工原则：模型只负责“读”（照片/PDF 识别、认表头、把规则文字译成结构化规则、读证明材料、判断两份材料是否同一成果）；所有分数由程序计算；无法从材料核实的事情交给用户在“确认页”决定。每个分数都能追溯到原始文件、工作表和行号。

主要能力：自动找表头、合并多级表头、等级制换算、对照名单认人、跨平台去重、冲突检测、缺考/缓考等状态、规则一句话修改、任何阶段修改材料或规则（版本化、可撤销）、结果三种状态（暂定 / 已确认 / 已被新版本替代）、Excel 导出、规则模板、记住用户的处理习惯（只预选不定案）、考核材料判重（证书编号/年份/拼音姓名等与语言无关的线索 + 模型分组，三档置信度）。

## 2. 技术栈与运行

- Python 3.12+（已在 3.13 验证），FastAPI + uvicorn，LangGraph（SqliteSaver 检查点，用 interrupt 实现“暂停等用户确认”），openpyxl / xlrd / pypdfium2 / Pillow / pypinyin。
- 前端：原生 JS 单页（`web/index.html`、`web/app.js`、`web/style.css`），无构建步骤，由后端以静态文件挂在根路径 `/`。
- 模型：任意 OpenAI 兼容接口，默认 DeepSeek `deepseek-flash`（需支持图片输入）。

启动（Windows）：

```powershell
# 首次会创建 .venv 并按 requirements.lock.txt 安装依赖
.\Start-Demo.ps1          # 或双击 启动Demo.cmd
.\Stop-Demo.ps1           # 或双击 停止Demo.cmd
```

等价的通用命令：

```bash
python -m venv .venv && .venv/Scripts/python -m pip install -r requirements.lock.txt
.venv/Scripts/python -m uvicorn app.main:app --host 127.0.0.1 --port 8017
```

健康检查：`GET /api/health` → `{"status":"ok","name":"知衡","version":"0.2.0","model":{...}}`。

### 环境变量

| 变量 | 默认 | 作用 |
|---|---|---|
| `B7_PORT` | 8017 | 端口（仅启动脚本使用） |
| `B7_DATA_DIR` | `./data` | 所有任务、数据库、上传文件、导出文件的目录 |
| `B7_LLM_BASE_URL` / `B7_LLM_MODEL` / `B7_LLM_API_KEY` | 空 | 启动时预置模型连接；也可运行后在界面“模型设置”或 `POST /api/settings/model` 设置 |
| `B7_MODEL_CACHE` | 1 | 模型结果按内容哈希缓存；测试中设为 0 |

**API Key 不得写入代码、配置文件、日志或提交记录。** 只通过环境变量或运行时接口传入。

## 3. 目录结构

```text
app/
  main.py           HTTP 接口、上传、任务队列（单线程 worker，任务串行执行）
  intake.py         判断流程类型、识别名单表、识别被考核人
  uploads.py        压缩包解包、同内容去重、规则文件识别
  documents.py      照片/PDF/Word 读取
  grades.py         表格解析、表头识别、字段映射、成绩值规范化
  scoring.py        评分规则结构与程序计算
  understand.py     开始前的说明（规则看不懂时的提问）
  workflow.py       成绩流程的 LangGraph 图、问题检测、确认、导出
  appraisal.py      考核方案拆指标、材料四种状态、计分
  appraisal_flow.py 考核流程的 LangGraph 图
  dedupe.py         考核材料是否同一成果
  habits.py         记住用户的处理习惯
  versions.py       修改/撤销/版本快照/结果状态
  export_xlsx.py    Excel 导出、记录在原文件中的位置
  model.py          模型调用（OpenAI 兼容）、缓存
  store.py          SQLite：tasks / events / decisions / versions / prefs / templates / cache
web/                前端单页
fixtures/           内置合成样例（成绩、考核）
scripts/            生成样例的脚本
tests/              pytest，当前 109 项全部通过
eval/               判重等离线评测（需真实模型）
data/               运行数据（不入库）
```

`data/` 下：`workspace.sqlite3`（业务数据）、`checkpoints.sqlite3`（LangGraph 检查点）、`tasks/<task_id>/input|output/`（上传文件与导出文件）。

## 4. 任务生命周期

```text
POST /api/tasks（上传 + 规则） → queued → running
  → waiting_review（pending.stage = understand | mapping | confirm）
  → POST /review → queued → running → … → completed
其他状态：failed（可 retry）、stopped（用户中止，可 retry）、cancelled（已切换为另一种流程）
```

- `understand`：规则有看不懂的地方，先问用户（问题格式 `problem / need / options`）。
- `mapping`：极少数情况下系统看不出哪列是学号/成绩，请用户指定。
- `confirm`：一页确认：规则的大白话理解、需要用户决定的问题（有建议的已预选）、结果预览。
- 任何阶段都可 `POST /modify` 增删材料、改规则或撤回某个决定，生成新版本；`POST /undo` 回到上一版本。

前端轮询 `GET /api/tasks/{id}` 观察 `status`、`step`、`result`。

## 5. HTTP 接口

所有接口在 `/api/` 下，错误统一返回 `{"detail": "中文说明"}`（400 参数错误，404 不存在，409 状态不允许）。

| 方法与路径 | 用途 |
|---|---|
| `GET /api/health` | 健康检查 |
| `GET /api/config` | 模型状态、样例、限制、用户偏好、规则模板、处理习惯 |
| `POST /api/prefs` | `{identity, flow, habits}` 常用身份/流程、是否记住习惯 |
| `POST /api/settings/model` | `{base_url, model, api_key}` 连接模型；`DELETE` 断开；`POST .../test` 测试 |
| `GET /api/tasks` | 任务列表 |
| `POST /api/tasks` | **主入口**，`multipart/form-data`：`files`（可多个，支持 zip）、`rules_text`、可选 `kind`（`grades`/`appraisal`，不填自动判断）、`name`、`course`、`people`、`template` |
| `GET /api/tasks/{id}` | 任务详情（含 `result.pending` 确认页数据、版本号、结果状态） |
| `POST /api/tasks/{id}/review` | 提交确认，JSON：`decisions`、`fills`、`mappings`、`answers`（成绩）；`materials`、`judgements`、`relations`、`scheme_answers`（考核） |
| `POST /api/tasks/{id}/revise` | `{text}` 一句话修改规则（如“期中改成30%”） |
| `POST /api/tasks/{id}/reparse` / `rounding` / `adjust` | 重新理解规则 / 改小数位 / 完成后修改某人某项 |
| `POST /api/tasks/{id}/modify` | multipart：`files`、`remove`（JSON 下标数组）、`rules_text`、`revoke`、`reopen` |
| `POST /api/tasks/{id}/undo` / `stop` / `retry` / `switch` | 撤销版本 / 中止 / 继续 / 切换流程 |
| `POST /api/tasks/{id}/template` | `{name}` 把已确认规则存为模板；`DELETE /api/templates/{id}` |
| `DELETE /api/habits/{key}` | 删除一条处理习惯 |
| `GET /api/tasks/{id}/download/{file}` | `results.xlsx`、`grades.csv`、`totals.csv`、`summary.csv`、`audit.json`、`report.html` |
| `GET /api/tasks/{id}/locate?file=&sheet=&row=` | 某条记录在原文件中的位置 |
| `GET /api/tasks/{id}/sources/{index}` | 原始文件（`?inline=1` 图片/文本内嵌显示） |
| `DELETE /api/tasks/{id}` | 永久删除任务及其文件（运行中拒绝） |
| `POST /api/demo/{course|grades|appraisal}` | 运行内置合成样例 |
| `POST /api/rules/extract` | 从上传的规则文件读出文字 |

限制：每任务 40 个文件、单文件 20MB、单表 10000 行、单份 PDF 30 页、规则 6000 字。

## 6. 合并方式建议

按改动从小到大：

1. **独立进程 + 跳转/新窗口（推荐）**：宿主应用启动 B7 进程（`uvicorn app.main:app --port 8017`），菜单项打开 `http://127.0.0.1:8017/`。零改动。
2. **iframe 嵌入**：`<iframe src="http://127.0.0.1:8017/">`。页面自己发出的请求是同源的，可以正常工作。
3. **宿主后端直接调 B7 接口**：服务端到服务端调用不带 `Origin` 头，可以直接用。

需要注意的两个地方：

- **跨来源保护**：`app/main.py` 的 `local_origin` 中间件会拒绝 `Origin` 与 `Host` 不一致的请求（返回 403）。如果宿主前端从自己的域名直接 `fetch` B7 接口，或通过反向代理且改写了 `Host`，会被拦截。处理办法：反向代理保留原 `Host`，或在该中间件里加入宿主来源的白名单。不要整个删掉这项检查。
- **路径前缀**：前端用的是绝对路径 `/api/...`，静态文件挂在根 `/`。如果要挂到子路径（如 `/b7/`），需要同时改 `web/app.js` 里的 `api()` 路径前缀和 `index.html` 的资源路径；更简单的是给 B7 单独一个端口或子域名。

不建议把 B7 的模块拆散后并入宿主的 FastAPI 应用：任务队列（`main.pool`，单 worker）、LangGraph 检查点连接（`workflow.checkpointer`）和 `store.DATA` 都是模块级单例，拆开后容易出现两份数据库或任务并发执行。确实要合进同一个进程，用 `host_app.mount('/b7', b7_app)` 整体挂载，并处理上面的路径前缀。

打包为桌面程序（PyInstaller 等）时：把 `web/`、`fixtures/` 作为数据文件带上（代码通过 `store.ROOT` 定位）；把 `B7_DATA_DIR` 指到用户可写目录；不要把 `.venv/`、`data/`、`logs/` 打进包。

## 7. 合并时不能改变的约束

- API Key 只在内存或环境变量中，不写盘、不进日志、不进提交。
- 计算由程序完成，不让模型直接给分数；模型摘录的原文必须保留“与原文核对”的标记。
- 处理习惯、模型建议只能“预选”，必须由用户确认后才生效。
- 用户数据只在用户主动删除时删除；合并脚本不得清空 `data/`。
- 评测答案文件（`评测答案_不要上传`、`03_评测答案_不要交给模型.xlsx`）只用于本地对照，不得交给模型，也不得打进包。
- 参考文献模块属于合作方，不在 B7 内，不要重复加入。
- 不自动发邮件、不自动提交、不访问学校系统或任何账号。

## 8. 合并后的验证

```bash
.venv/Scripts/python -m pytest -q          # 预期 109 passed，不需要模型
```

手动冒烟（需要模型）：
1. 打开工作台，在“模型设置”连接模型。
2. “新建任务”页运行三个样例：课程总评、多平台成绩归并、辅导员考核。各自应停在确认页，确认后状态为 completed，能下载 `results.xlsx`。
3. 在一个已完成任务上点“修改材料或规则”，删掉一个文件，应生成新版本，旧结果标为“已被替代”；点撤销能回到原版本。

已验证的效果（合成数据，DeepSeek `deepseek-flash`）：两个 50 人班级的边界测试集，A 班与标准结果 0 差异，B 班仅 1 处为数据集声明“系统不可能发现”的项；考核判重 72 对材料全部判对。只覆盖合成数据，不代表真实数据上的准确率。

## 9. 已知限制

- 照片中的记录只能定位到哪张照片，不能框出具体位置。
- 处理习惯按“问题类型”记，不区分课程；只存在本机 `data/` 中。
- 任务串行执行，同时只处理一个任务。
- 只在 Windows 上验证过启动脚本；代码本身不依赖 Windows。
